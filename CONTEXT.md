**3. MCP (Context7).** Подключение заняло заметно больше, чем "просто написать `.mcp.json`", и это отдельный полезный урок:
- Первая ручная правка `.mcp.json` была валидным JSON, но Claude Code её не регистрировал — сервер не был виден ни в `/mcp`, ни в `claude mcp list`, без единой ошибки. Причина: регистрация "pending/approved" ведётся отдельно от содержимого файла и создаётся только через `claude mcp add`, а не просто чтением файла.
- Дополнительно мешало по пути: (а) истёкший логин в Claude Code, из-за которого `/login` сначала даже не показывал экран входа; (б) случайный запуск `claude mcp add` не из папки проекта — создал второй, лишний `.mcp.json` в домашней директории; (в) застрявшее состояние "approved/rejected" для этого проекта, оставшееся с первых неудачных попыток — потребовался `claude mcp reset-project-choices`, чтобы approval-экран вообще появился.
- После устранения всего этого approval-экран сработал штатно (New MCP server found → Use this and all future MCP servers in this project), `context7` подключился, и настоящий вызов подтверждён: "Called context7 2 times" — реальный `resolve-library-id` + запрос документации по `scipy.stats.chisquare`, а не текст, придуманный моделью.

**Вывод по трём типам провала из занятия (скилл не выбрался / сработал не туда / вызов только текстом):** в финальном состоянии не произошёл ни один — но по пути к рабочему MCP пришлось пройти через скрытую разновидность первого типа: сервер был в файле, но не "выбран", потому что approval-состояние для него не зарегистрировалось. Урок на будущее: если MCP-сервер не появляется в `/mcp`, первым делом проверять не синтаксис `.mcp.json` (он может быть абсолютно корректным), а именно состояние approval — `claude mcp list` из правильной директории и, при необходимости, `claude mcp reset-project-choices`.
